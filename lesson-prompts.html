Lesson 7 — Prompts, temperature, and attacks

Domain 3.2 plus the inference knobs from 3.1. Practice writing the words, not just reading them.

A prompt has parts

  • Instruction — what to do (“summarise in 5 bullets”).
  • Context — facts, retrieved chunks, conversation history.
  • Input — the user’s question.
  • Output format — JSON, table, “cite sources.”
  • Negative prompt — what not to do (“do not invent clause numbers”).

Context engineering is bigger than the instruction sentence. It is everything you stuff into the window: system prompt, tools, memory, RAG chunks.

Techniques

NameTeach it
Zero-shotInstruction only
Single-shot / one-shotOne example
Few-shotA few examples. Also called in-context learning. Weights do not change.
Chain-of-thought“Think step by step” for math or multi-hop reasoning
TemplateReusable structure with variables
Prompt ManagementBedrock stores versions so you can roll forward/back without redeploying folklore

Best practices from the guide: be specific and concise, experiment, use Guardrails for safety, try more than one wording.

Knobs

Temperature low (0–0.3) for policy, support, RAG. High for brainstorming. Top-p is another creativity limiter. Max tokens caps length and output cost. Stop sequences cut the model off.

Attacks

NameWhat happened
JailbreakUser talks the model past safety
Injection / hijackA webpage or PDF says “ignore previous instructions”
PoisoningBad examples or bad KB documents
ExposureThe model leaks the system prompt or a secret

Defence is infrastructure: Guardrails, treat untrusted text as data, never put secrets in prompts (Secrets Manager), least-privilege tools, grounding checks. A sentence in the system prompt is not a guarantee.
