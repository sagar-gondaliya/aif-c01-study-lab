Lesson 5 — Agents, tools, MCP, AgentCore

2026 exam guide added this on purpose. Learn the nouns. You will not write the agent loop.

Chatbot versus agent

A normal FM call: user text in, model text out.
An agent: the model decides it needs a tool (search, ticket API, calculator), calls it, reads the result, and continues. That loop is often called ReAct (reason + act).

Pieces you must name

  • Tools / function calling — APIs the agent is allowed to use.
  • Memory — short-term (this chat) vs long-term (across sessions).
  • MCP (Model Context Protocol) — a standard way to connect agents to external tools and data. The agent is a client; the tool is an MCP server.
  • Multi-agent — specialist agents coordinated (research agent + writer agent). On AWS: Strands Agents.
  • Orchestration — who runs the loop. AgentCore Runtime, or a fixed workflow when steps never change.

AgentCore (in-scope 2026)

PartJob
RuntimeServerless place the agent process runs
GatewayMCP-compatible tool connectivity
IdentityWho the agent is; maps to least-privilege access
PolicyWhat tools and data it may touch — enforced outside the model’s “please”
Memory / ObservabilityState and traces
A prompt-injected model must not be able to authorise a dangerous tool call. That is why Policy and IAM exist. Guardrails filter content; they do not replace identity.

When not to use an agent

If the process is always “extract → summarise → store,” that is a fixed workflow, not an open-ended agent. The exam still rewards “agent” when the next step depends on the question and many tools exist.

Productised vs custom

Amazon Q / Quick / Kiro — you use an assistant AWS already built.
Bedrock Agents + AgentCore + Strands — you build an agent for your APIs.
