Lesson 6 — RAG, the most important pattern

This lesson absorbs the useful RAG parts of your AIP-C01 notes, cut down to Practitioner depth. Domain 3 lives or dies here.

The idea in one breath

The FM does not know your intranet. You retrieve the relevant passages, augment the prompt with them, then generate. That is grounding. Citations become possible. When the policy changes next month you re-ingest documents — you do not retrain a 70-billion-parameter model.

Question → turn the question into an embedding → similarity search in a vector store → take the top chunks → prompt = instructions + chunks + question → FM answers (ideally: “according to doc X”)

AWS default

Amazon Bedrock Knowledge Bases does ingest, chunk, embed, store, retrieve, and generate. Point it at S3 (or a connector). If the stem says “minimise custom code,” this is the answer.

Where embeddings live

Official vector options: OpenSearch Service, Aurora (pgvector), Neptune, RDS for PostgreSQL.

  • S3 holds the source files. It cannot do similarity search by itself.
  • MemoryDB is out of scope in 2026. Do not pick it.
  • DynamoDB / ElastiCache are not the exam’s vector answer.

Chunking (from your notes)

  • Fixed size — simple, e.g. ~300 tokens. Fine for uniform docs.
  • Hierarchical (parent/child) — retrieve a small hit, return the larger section. Legal contracts, manuals.
  • Semantic — split when the topic changes.

Irrelevant chunks → too large or mixed topics. Missing context → too small; add overlap or hierarchy.

When retrieval is the problem (your notes, exam gold)

  • Hybrid search — keywords (error codes, SKUs) plus vectors. OpenSearch does this.
  • Metadata filters — year=2023, dept=Legal, before search.
  • Re-ranking — fetch 50, keep the best 5 with a second model.
  • Vector indexes do not auto-update. New S3 objects need an ingestion job.

The trap you will see

Wrong documents in the prompt → fix retrieval (chunk, hybrid, filter, re-rank).
Right documents, wrong sentence → fix generation (prompt, temperature, model, Guardrails grounding).

RAG versus fine-tune versus prompt

Changing facts, citations, private knowledge → RAG.
Format and a few examples → prompt / few-shot.
Stable style or domain voice with labeled pairs → fine-tune.
Need a cheaper student model → distillation.
Build a new FM → almost never.
